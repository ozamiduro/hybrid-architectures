# Setup AWS: Amazon EKS y Amazon ECR

Este documento contiene **únicamente la preparación de la infraestructura y los servicios de AWS** necesarios para ejecutar el laboratorio Tech Store.

Incluye:

- Creación del clúster Amazon EKS mediante `eksctl`.
- Configuración de OIDC, grupos de nodos y complementos de EKS.
- Configuración de los permisos IAM asociados a los nodos.
- Creación de repositorios privados en Amazon ECR.
- Autenticación de Docker y publicación de imágenes en ECR.
- Instalación del AWS Load Balancer Controller, requerido por el Ingress de la aplicación.

> Los manifiestos y la configuración propia de la aplicación Kubernetes se encuentran en `k8s/README.md` y en el README principal del paquete.

## 1. Requisitos

Instala y configura las siguientes herramientas:

- AWS CLI
- `eksctl`
- `kubectl`
- Helm
- Docker

Verifica las credenciales de AWS:

```bash
aws sts get-caller-identity
```

Asegúrate de tener permisos suficientes para crear recursos de EKS, EC2, IAM, VPC, ECR y los recursos relacionados.

## 2. Configuración del clúster EKS

El laboratorio utiliza el archivo `cluster.yaml` con la siguiente configuración:

| Parámetro | Valor |
|---|---|
| Nombre del clúster | `eks-lab-tec` |
| Región | `us-east-1` |
| Versión de Kubernetes | `1.35` |
| OIDC | Habilitado |
| Grupo de nodos | `workers-spot` |
| Tipo de instancia | `t3.medium` |
| Capacidad inicial | 1 nodo |
| Capacidad mínima | 1 nodo |
| Capacidad máxima | 2 nodos |
| Disco por nodo | 30 GiB |
| Tipo de volumen | `gp3` |

### 2.1 Crear el clúster

Desde el directorio donde se encuentra `cluster.yaml`, ejecuta:

```bash
eksctl create cluster -f cluster.yaml
```

El proceso puede tardar varios minutos.

Valida el acceso al clúster:

```bash
kubectl get nodes
kubectl get pods -A
```

### 2.2 Configuraciones incluidas en `cluster.yaml`

#### OIDC

```yaml
iam:
  withOIDC: true
```

Habilita el proveedor IAM OIDC para que las aplicaciones y controladores de Kubernetes puedan utilizar roles IAM mediante ServiceAccounts, según el mecanismo de integración configurado.

#### Grupo de nodos

El grupo administrado `workers-spot` utiliza instancias `t3.medium`, con un tamaño inicial de un nodo y escalamiento entre uno y dos nodos.

Cada nodo tiene un volumen de 30 GiB de tipo `gp3`, destinado a proporcionar capacidad de almacenamiento para las cargas del laboratorio.

#### Políticas IAM para los nodos

El archivo habilita las siguientes políticas administradas por `eksctl` mediante `withAddonPolicies`:

- `autoScaler`: permisos relacionados con el escalamiento de los nodos.
- `ebs`: permisos relacionados con el uso de volúmenes EBS.
- `cloudWatch`: permisos para integración con CloudWatch.
- `albIngress`: permisos para que el AWS Load Balancer Controller gestione balanceadores de carga.

> Para entornos productivos, revisa el principio de mínimo privilegio y evalúa utilizar roles IAM específicos para cada componente mediante OIDC/IRSA o el mecanismo recomendado por la versión de EKS.

#### Add-ons de EKS

El archivo configura:

- `vpc-cni`, con las políticas de red habilitadas mediante `enableNetworkPolicy: "true"`.
- `aws-ebs-csi-driver`, utilizado para aprovisionar volúmenes persistentes EBS.

Verifica los add-ons:

```bash
aws eks list-addons   --cluster-name eks-lab-tec   --region us-east-1
```

Verifica las StorageClasses disponibles:

```bash
kubectl get storageclass
```

## 3. Permisos IAM para Amazon ECR

Se requieren permisos para dos escenarios:

### 3.1 Usuario o rol que publica imágenes

El usuario o rol que ejecuta AWS CLI necesita permisos para:

- Crear repositorios.
- Obtener el token de autenticación.
- Subir imágenes a ECR.

Como referencia, se requieren acciones como:

```text
ecr:CreateRepository
ecr:GetAuthorizationToken
ecr:BatchCheckLayerAvailability
ecr:InitiateLayerUpload
ecr:UploadLayerPart
ecr:CompleteLayerUpload
ecr:PutImage
```

### 3.2 Nodos del clúster

Los nodos necesitan permisos de lectura para descargar imágenes privadas desde ECR.

Valida que el rol de los nodos tenga permisos equivalentes a:

```text
AmazonEC2ContainerRegistryReadOnly
```

La asignación exacta debe verificarse en el rol IAM creado para el grupo de nodos.

## 4. Crear los repositorios en Amazon ECR

El laboratorio utiliza tres imágenes:

- `order-service`
- `product-service`
- `web-app`

### Opción A: Consola de AWS

1. Ingresa a la consola de AWS.
2. Selecciona la región `us-east-1`.
3. Busca **Amazon ECR**.
4. Ingresa a **Repositories**.
5. Selecciona **Create repository**.
6. Selecciona visibilidad **Private**.
7. Crea los repositorios con estos nombres:

```text
order-service
product-service
web-app
```

### Opción B: AWS CLI

```bash
aws ecr create-repository   --repository-name order-service   --region us-east-1

aws ecr create-repository   --repository-name product-service   --region us-east-1

aws ecr create-repository   --repository-name web-app   --region us-east-1
```

Valida los repositorios:

```bash
aws ecr describe-repositories   --region us-east-1
```

## 5. Autenticar Docker con Amazon ECR

Obtén el ID de la cuenta y define la URI base del registro:

```bash
export AWS_REGION=us-east-1
export ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
export REGISTRY_URI="${ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com"
```

Autentica Docker:

```bash
aws ecr get-login-password --region "$AWS_REGION"   | docker login       --username AWS       --password-stdin "$REGISTRY_URI"
```

## 6. Publicar las imágenes en ECR

Construye las imágenes desde el proyecto y etiquétalas con la URI de ECR.

Ejemplo:

```bash
docker build -t order-service:1.1.0 ./order-service
docker build -t product-service:1.1.0 ./product-service
docker build -t web-app:1.1.0 ./web-app
```

Etiqueta las imágenes:

```bash
docker tag order-service:1.1.0 "$REGISTRY_URI/order-service:1.1.0"
docker tag product-service:1.1.0 "$REGISTRY_URI/product-service:1.1.0"
docker tag web-app:1.1.0 "$REGISTRY_URI/web-app:1.1.0"
```

Publica las imágenes:

```bash
docker push "$REGISTRY_URI/order-service:1.1.0"
docker push "$REGISTRY_URI/product-service:1.1.0"
docker push "$REGISTRY_URI/web-app:1.1.0"
```

Verifica las imágenes:

```bash
aws ecr list-images   --repository-name order-service   --region "$AWS_REGION"

aws ecr list-images   --repository-name product-service   --region "$AWS_REGION"

aws ecr list-images   --repository-name web-app   --region "$AWS_REGION"
```

## 7. Resultado esperado

Al finalizar este documento tendrás:

- El clúster `eks-lab-tec` operativo.
- Los add-ons principales configurados.
- Los nodos disponibles para ejecutar cargas de trabajo.
- Los repositorios privados creados en ECR.
- Las imágenes de la aplicación publicadas en ECR.

Al finalizar el laboratorio se recomienda eliminar los recursos creados

```bash
eksctl delete cluster \
  --name eks-lab-tec \
  --region us-east-1
```
