# TechStore - Laboratorio Kubernetes en Amazon EKS

## 1. Objetivo

Desplegar en **Amazon EKS** la misma aplicación TechStore utilizada en los laboratorios anteriores de Docker y Minikube:

- PostgreSQL 16
- `product-service` - Java 21 / Spring Boot
- `order-service` - Java 21 / Spring Boot
- `web-app` - React + Nginx

El laboratorio introduce el paso de Kubernetes local a Kubernetes administrado en AWS y agrega servicios propios de EKS:

- Amazon ECR para imágenes privadas
- Amazon EBS mediante EBS CSI Driver para persistencia
- AWS Load Balancer Controller
- Application Load Balancer (ALB)
- Ingress Kubernetes
- DNS interno mediante Services
- ConfigMap y Secret
- Readiness/Liveness probes
- Requests y limits
- Escalamiento de réplicas

> **Importante:** este laboratorio es educativo. PostgreSQL se ejecuta dentro de Kubernetes para que el alumno practique PVC/EBS. En una arquitectura productiva normalmente se evaluaría Amazon RDS/Aurora para la base de datos.

# 3. Configuración de Credenciales AWS
Necesitarás una cuenta de AWS activa . A continuación, los pasos para obtener los accesos necesarios:

1.  Ingresa a la consola de AWS (https://console.aws.amazon.com/) y dirígete al servicio **IAM** .
2.  Ve a `Users -> Create user` (puedes llamarlo `eks-admin`) .
3.  Selecciona `Attach policies directly` y asígnale la política `AdministratorAccess` .
4.  Una vez creado, entra al usuario, ve a `Security credentials` y haz clic en `Create access key` .
5.  Selecciona el caso de uso `Command Line Interface (CLI)` .
6.  **Importante:** Copia tu `AWS Access Key ID` y `AWS Secret Access Key` (este último solo se muestra una vez) .

Finalmente, vincula estas credenciales a tu entorno local ejecutando:
```bash
aws configure
```
Se te solicitará ingresar tus credenciales, la región (`us-east-1` por defecto para este laboratorio) y el formato de salida (`json`) .
Para validar que tienes acceso, ejecuta :
```bash
aws sts get-caller-identity
```

# 6. Configurar las imágenes de Kubernetes

Los manifests contienen estos marcadores:

```text
PRODUCT_IMAGE
ORDER_IMAGE
WEB_IMAGE
```

Puedes reemplazarlos automáticamente desde Git Bash/Linux/macOS con el script incluido:

```bash
export AWS_REGION=us-east-1
export TAG=1.1.0
./scripts/configure-images.sh
```

En PowerShell:

```powershell
./scripts/configure-images.ps1 -AwsRegion us-east-1 -Tag 1.1.0
```

También puedes realizar el reemplazo manualmente usando la URI de ECR.

```bash
grep 'image:' k8s/05-product-service.yaml
```

> Si trabajas en PowerShell, puedes editar los tres valores `image:` directamente con la URI que obtengas mediante `aws sts get-caller-identity`.

# 7. Desplegar PostgreSQL como StatefulSet

Primero crea el namespace:

```bash
kubectl apply -f k8s/00-namespace.yaml
```

Secret:

```bash
kubectl apply -f k8s/01-postgres-secret.yaml
```

StorageClass:

```bash
kubectl apply -f k8s/02-storageclass.yaml
```

Ahora despliega PostgreSQL como `StatefulSet`:

```bash
kubectl apply -f k8s/03-postgres-statefulset.yaml
```

El manifiesto crea dos recursos relacionados:

- Service headless `postgres` (`clusterIP: None`)
- StatefulSet `postgres`

El StatefulSet crea automáticamente el PVC mediante `volumeClaimTemplates`. Para la primera réplica el nombre esperado es:

```text
postgres-data-postgres-0
```

Comprueba:

```bash
kubectl get statefulset -n techstore
kubectl get pods -n techstore
kubectl get pvc -n techstore
kubectl get pv
```

Cuando PostgreSQL esté listo, debe aparecer el Pod:

```text
postgres-0   1/1   Running
```

Y el PVC debe quedar en `Bound`.

```bash
  -n techstore \
  --rm -it \
  --image=curlimages/curl:8.10.1 \
  --restart=Never \
  -- curl -s http://order-service:8082/api/orders
```

Crea una orden:

```bash
kubectl run curl-test \
  -n techstore \
  --rm -it \
  --image=curlimages/curl:8.10.1 \
  --restart=Never \
  -- curl -s -X POST http://order-service:8082/api/orders \
```

```bash

  -n techstore \
  --rm -it \
```

# 19. Troubleshooting

## Pod en `ImagePullBackOff`

```bash
kubectl describe pod <POD> -n techstore
```

Comprueba:

```bash
aws ecr list-images --repository-name product-service --region us-east-1
```

Y que la URI del manifest sea correcta:

```bash
grep image: k8s/05-product-service.yaml
```

Si el nodo no puede descargar ECR, revisa que el rol de los nodos tenga permisos de lectura. El setup AWS del curso contempla `AmazonEC2ContainerRegistryReadOnly` para los nodos.

## PVC en `Pending`

```bash
kubectl get pvc -n techstore
kubectl describe pvc postgres-data-postgres-0 -n techstore
kubectl get storageclass
```

Comprueba el EBS CSI Driver:

```bash
kubectl get pods -n kube-system | grep ebs
```

## ALB no aparece

```bash
kubectl describe ingress techstore-ingress -n techstore
```

Revisa el controller:

```bash
kubectl get pods -n kube-system | grep aws-load-balancer
kubectl logs -n kube-system deployment/aws-load-balancer-controller
```

Comprueba que el Ingress tenga:

```yaml
spec:
  ingressClassName: alb
```

## `order-service` no llega a `product-service`

Comprueba:

```bash
kubectl get svc -n techstore
kubectl get endpoints -n techstore product-service
```

Debe existir al menos un endpoint.

Prueba DNS desde un Pod temporal:

```bash
kubectl run dns-test \
  -n techstore \
  --rm -it \
  --image=busybox:1.36 \
  --restart=Never \
  -- nslookup product-service
```

# 23. Limpieza

Primero elimina la aplicación:

```bash
kubectl delete namespace techstore
```

Esto elimina los Deployments, Services, Ingress, Secret, PVC y demás recursos dentro del namespace.

Comprueba:

```bash
kubectl get namespace techstore
```

> Como la StorageClass usa `reclaimPolicy: Delete`, el volumen EBS creado dinámicamente para el PVC será eliminado cuando corresponda al eliminar el PVC. Para un laboratorio esto ayuda a evitar costos residuales.

Si también deseas eliminar ECR:

```bash
aws ecr delete-repository \
  --repository-name product-service \
  --region us-east-1 \
  --force

aws ecr delete-repository \
  --repository-name order-service \
  --region us-east-1 \
  --force

aws ecr delete-repository \
  --repository-name web-app \
  --region us-east-1 \
  --force
```

Y si el clúster fue creado solo para este laboratorio:

```bash
eksctl delete cluster \
  --name eks-lab-tec \
  --region us-east-1
```

Se recomienda eliminar el clúster al terminar para evitar recursos/costos innecesarios.
